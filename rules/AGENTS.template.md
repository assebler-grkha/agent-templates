# Project Rules & Token Efficiency Protocol

## 1. Порядок поиска (Правило 3 уровней — строго по приоритету)
1. **Слой 1 — Граф связей (`codebase-memory-mcp`)**:
   - `search_graph(pattern)` — поиск функции, класса, маршрута.
   - `trace_path(symbol, direction)` — поиск вызывающих/вызываемых связей.
   - `get_code_snippet(symbol)` — точечное чтение тела нужной функции/класса БЕЗ чтения всего файла.
2. **Слой 2 — Долгосрочная память (`agent_memory` / `agentdb`)**:
   - Перед сложными архитектурными задачами проверь готовые решения: `search_memory(query)` / `agentdb_search(query)`.
3. **Слой 3 — Текстовый поиск (только если нет в графе/памяти)**:
   - `grep` / `glob` с обязательными фильтрами путей и расширений (исключая `node_modules`, `dist`, `.git`, `.venv`).

## 2. Запрет на «жадное» чтение файлов (No Greedy Reads)
- **ЗАПРЕЩЕНО** читать весь файл целиком, если в нем больше 100 строк или нужен только фрагмент.
- Для чтения фрагментов используй `view_file` с `StartLine`/`EndLine` или `get_code_snippet`.
- Запрещено читать файлы сборки, логи (`*.log`), lock-файлы (`package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`).
- Запрещено повторно перечитывать один и тот же файл без изменений в рамках задачи.

## 3. Оптимизация терминала и правок
- Длинные выводы команд фильтруй через сжатие (`rtk`, `head`, `Select-Object -First`).
- Используй компактные флаги (`git status -s`, `--quiet`, `-q`).
- Формируй и проверяй правки перед применением, избегая циклов мелких правок по 1 строке.

## 4. Минимализм и качество кода (YAGNI / Aislop)
- Не создавай вспомогательные абстракции, фабрики или утилиты «на будущее».
- Перед сдачей задачи обязателен локальный запуск проверки качества: `npx aislop scan`.
