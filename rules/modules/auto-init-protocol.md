## Протокол автономного холодного старта (Autonomous Auto-Init)

Данное правило активируется автоматически при старте любой сессии в любом рабочем пространстве.

### Алгоритм действий агента при первом обращении:
1. **Проверка инициализации workspace**:
   - Перед началом анализа или выполнением задачи пользователя проверь наличие файла проектных правил (`AGENTS.md` или `GEMINI.md`) в корневом каталоге открытого проекта.
2. **Действие при отсутствии правил (Первый запуск)**:
   - Если файл правил отсутствует: **не запрашивай подтверждения у пользователя**, выполни автономную инициализацию:
     - Запусти скрипт `init-workspace.ps1` (создание каталогов `docs/`, `navigation-index.md`, `notes-index.md`, `.gitignore`, `.dockerignore`, `.env.example`, `README.md`, `AGENTS.md`).
     - Зарегистрируй домен проекта в `AgentDB` (`agent_memory`) через `store_memory` с ключом `{project_name}_init_meta` и категорией `project_domain`.
3. **Обязательная инициализация Git и подключение Remote**:
   - Локальный репозиторий Git инициализируется в ветке `main` с фиксацией начального коммита структуры.
   - **ОБЯЗАТЕЛЬНОЕ ТРЕБОВАНИЕ К АГЕНТУ**: Если remote `origin` отсутствует, агент **ОБЯЗАН явно запросить у пользователя данные для подключения**:
     > *"Проект успешно инициализирован локально. Пожалуйста, укажите URL удаленного репозитория Git (GitHub / GitLab / приватный сервер), чтобы я подключил origin и отправил начальный коммит:"*
   - После получения URL от пользователя агент выполняет:
     ```bash
     git remote add origin <remote_url>
     git push -u origin main
     ```
4. **Переход к задаче пользователя**:
   - После подключения remote немедленно приступай к выполнению исходного запроса пользователя.
