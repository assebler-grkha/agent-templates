# ADR 0001: Инициализация базовой архитектуры и агентных стандартов

- **Статус**: Принято
- **Дата**: 2026-09-22
- **Автор**: Workspace Architect Agent

## Контекст и проблематика
Для эффективной разработки с помощью ИИ-агентов (Antigravity, OpenCode, Claude Code) требуется детерминированная структура проекта, стандарты файловой гигиены и механизм экономии токенов при чтении контекста.

## Рассмотренные варианты
1. **Монолитные правила в одном файле (15-30 КБ)**: приводят к переполнению контекстного окна и росту задержек.
2. **Модульная система с динамическими зонами (< 3.5 КБ) и вторичными индексами**: правила содержат только критически важные ограничения и ссылки на детальные индексы (`docs/navigation-index.md`, `docs/notes-index.md`).

## Решение
Принят вариант 2:
- Правила проекта делятся на `ZONE: IMMUTABLE` (константы) и динамические секции (`NAVIGATION`, `GOTCHAS`, `FOCUS`).
- Общий размер правил строго ограничен 3.5 КБ.
- Навигация по файлам и символам делегирована в `docs/navigation-index.md`.
- Обязательная инициализация Git и привязка к remote-репозиторию при холодном старте.

## Последствия
- **Позитивные**: Снижение расхода токенов на системные инструкции на 70–85%, быстрый холодный старт (< 5 с), отсутствие галлюцинаций по структуре кодовой базы.
- **Негативные / Риски**: Агенту требуется соблюдать 3-уровневый протокол поиска (`codebase` -> `agent_memory` -> `grep`) вместо чтения файлов подряд.
