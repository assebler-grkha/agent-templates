# Спецификация динамических проектных правил и навигационных индексов

Настоящая спецификация определяет стандарт ведения проектных правил (`AGENTS.md` / `GEMINI.md`), протокол их автономной актуализации ИИ-агентом, правила изоляции контекста, использование внешних навигационных индексов и привязку к доменам в `AgentDB` (`agent_memory`).

---

## 1. Архитектурный принцип двухуровневого контекста

1. **Горячий уровень (Hot Tier — `AGENTS.md`)**:
   - Загружается в каждое окно диалога при каждом обращении.
   - **Жесткий лимит**: не более **3.5 КБ** (до 100 строк).
   - Запрещено дублировать глобальные правила (3-уровневый поиск, описания MCP, общие стандарты YAGNI).
   - Содержит только неизменяемое ядро, компактную карту верхнего уровня, до 5 свежих подвохов и ссылки на внешние индексы.

2. **Теплый/Холодный уровень (Warm/Cold Tier — Индексы и AgentDB)**:
   - **Документы-индексы (`docs/navigation-index.md`, `docs/notes-index.md`)**: детальные карты символов, роутинга и проектных заметок. Агент читает их точечно только при необходимости.
   - **AgentDB (`agent_memory` с `project = "<project_name>"`)**: внешняя SQLite-база для хранения полных ADR, архивных подвохов, контрактов API и истории архитектурных изменений.

---

## 2. Зонирование файла проектных правил (`AGENTS.md`)

Файл правил размечается специальными HTML-комментариями, определяющими права агента на модификацию:

```markdown
<!-- ZONE: IMMUTABLE: START -->
# Project: {PROJECT_NAME}
Inherits: global user_rules
Stack: {Язык, Фреймворк, БД, Сборщик}
Constraints: {Критические нерушимые требования разработчика}
<!-- ZONE: IMMUTABLE: END -->

<!-- ZONE: INDEX_POINTERS: START -->
## Project Indexes & Deep Routing
- Detailed Navigation Map: [docs/navigation-index.md](docs/navigation-index.md)
- Operational Notes & Decisions: [docs/notes-index.md](docs/notes-index.md)
- AgentDB Domain: `{PROJECT_NAME}`
<!-- ZONE: INDEX_POINTERS: END -->

<!-- ZONE: DYNAMIC: NAVIGATION: START -->
## Core Entry Points (Top 5-8)
- Main App: src/index.ts
- API Routes: src/api/
- Database Schema: prisma/schema.prisma
<!-- ZONE: DYNAMIC: NAVIGATION: END -->

<!-- ZONE: DYNAMIC: GOTCHAS: START -->
## Project Gotchas & Quirks (Max 5, FIFO)
- [YYYY-MM-DD] Описание неочевидного поведения сборки/окружения.
<!-- ZONE: DYNAMIC: GOTCHAS: END -->

<!-- ZONE: DYNAMIC: FOCUS: START -->
## Current Focus
- Текущая задача или фаза спринта (1-2 строки).
<!-- ZONE: DYNAMIC: FOCUS: END -->
```

---

## 3. Матрица прав и приоритетов модификации

| Зона | Кто может менять | Что разрешено записывать | Что запрещено |
|---|---|---|---|
| **ZONE: IMMUTABLE** | Только пользователь | Стек, базовые ограничения архитектуры, ссылку на глобальные правила. | Агенту **ЗАПРЕЩЕНО** изменять или удалять этот блок. |
| **ZONE: INDEX_POINTERS** | Агент и пользователь | Пути к специализированным документам-индексам (`docs/navigation-index.md` и др.). | Дописывать произвольный текст вне ссылок. |
| **ZONE: DYNAMIC: NAVIGATION** | Агент | Топ-5–8 главных точек входа и директорий проекта. | Детализацию функций и методов (их место — в `navigation-index.md`). |
| **ZONE: DYNAMIC: GOTCHAS** | Агент | До 5 критических граблей/подвохов запуска и сборки. | Логи задач, история диалогов, тривиальные ошибки кода. |
| **ZONE: DYNAMIC: FOCUS** | Агент | Текущая ключевая цель (1–2 предложения). | Многостраничные TODO-списки. |

---

## 4. Протокол вытеснения данных (Pruning & FIFO)

1. **Контроль лимита**:
   - Если размер `AGENTS.md` приближается к 3.5 КБ или превышает 100 строк — агент обязан провести очистку.
2. **Ротация Gotchas (FIFO)**:
   - Максимум 5 записей.
   - При добавлении 6-й записи самая старая или неактуальная запись переносится в `AgentDB`:
     ```python
     store_memory(
         key="{project}_gotcha_{topic}",
         project="{project_name}",
         category="archived_gotchas",
         content="..."
     )
     ```
   - Запись удаляется из `AGENTS.md`.
3. **Разгрузка навигации в документы-индексы**:
   - Если проект разрастается (микросервисы, десятки модулей), агент не раздувает блок навигации в `AGENTS.md`, а выносит детальные карты в `docs/navigation-index.md`.

---

## 5. Домен проекта в AgentDB (`agent_memory`)

При первой инициализации проекта или первом входе в репозиторий:
1. Агент определяет имя проекта `{project_name}` (из директории или манифеста).
2. Создается базовая доменная запись:
   - `key`: `{project_name}_init_meta`
   - `project`: `{project_name}`
   - `category`: `project_domain`
   - `content`: Дата инициализации, корневой путь, стек, ключевые цели.
3. Все последующие архитектурные заметки, объемные выводы аудитов и архивные решения сохраняются строго с флагом `project = "{project_name}"`.
