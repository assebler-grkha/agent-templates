# Канон структуры папок, файловой гигиены и жизненного цикла документации

Настоящий канон определяет единые стандарты организации рабочего пространства проекта для совместной работы разработчика и ИИ-агентов. Он обобщает опыт реальных проектов (`Nobel`, `TeleScope`, `LoopMaster`, `Harvester`, `Sinth`) и решает проблему хаоса файлов, раздувания контекста и устаревания документации.

---

## 1. Эталонное дерево директорий проекта

```text
<project_root>/
+-- AGENTS.md                      # Горячий контекст (< 3.5 КБ): навигация, до 5 gotchas, ссылки
+-- README.md                      # Витрина проекта: стек, быстрый старт (3 команды), архитектура
+-- .env.example                   # Эталон переменных окружения с описанием (без секретов!)
+-- .gitignore                     # Защита репозитория и контекста агента от тяжелых файлов
+-- .dockerignore                  # Высокоскоростной билд: исключение docs, tests, кэшей
+-- docs/                          # Единый центр проектной документации
|   +-- navigation-index.md        # Детальный реестр модулей и ключевых символов
|   +-- notes-index.md             # Реестр заметок, соглашений и ссылок на ADR
|   +-- specs/                     # Технические спецификации
|   |   +-- ui/                    # UI/UX спецификации экранов ({NN}_{screen}_spec.md)
|   |   \-- api/                   # Контракты API и схемы данных ({NN}_{service}_spec.md)
|   +-- decisions/                 # Архитектурные решения (ADR) ({NNNN}_{decision}.md)
|   +-- plans/                     # Планы активных спринтов и фаз ({phase}_plan.md)
|   +-- guides/                    # Инструкции по развертыванию, серверам, датасетам
|   +-- templates/                 # Внутренние шаблоны для создания новых документов
|   \-- archive/                   # Архив завершенных фаз и устаревших спек
+-- scratch/                       # Одноразовые скрипты агента (в .gitignore, не идут в git!)
+-- src/ (или apps/, lib/)         # Исходный код приложения
+-- tests/                         # Тесты (unit, integration, e2e)
\-- scripts/                       # Проектные скрипты автоматизации и миграций
```

## 2. Основные категории документов и правила именования

| Категория | Где располагается | Формат имени | Статусы | Назначение |
|---|---|---|---|---|
| **UI/UX Спецификации** | `docs/specs/ui/` | `{NN}_{screen_slug}_spec.md`<br>*(например: `01_auth_spec.md`, `17_admin_users_spec.md`)* | `Draft`, `Active`, `Implemented`, `Deprecated` | Анатомия компонентов, Penpot ID, состояния Светлой/Темной тем, валидация полей, действия пользователя. |
| **API Контракты** | `docs/specs/api/` | `{NN}_{service_slug}_spec.md`<br>*(например: `01_auth_api_spec.md`)* | `Draft`, `Active`, `Implemented` | Эндпоинты, методы, структуры запросов/ответов, Zod/Pydantic-типы, коды ошибок. |
| **Архитектурные решения (ADR)** | `docs/decisions/` | `{NNNN}_{decision_slug}.md`<br>*(например: `0001_db_orm_selection.md`)* | `Proposed`, `Accepted`, `Deprecated` | Фиксация выбора технологий, библиотек или подходов с обоснованием и рисками. |
| **Планы спринтов / фаз** | `docs/plans/` | `{phase_slug}_plan.md`<br>*(например: `phase1_stabilize_plan.md`, `sprint_2_reviews_plan.md`)* | `In Progress`, `Completed` | Чеклисты задач по фазе со ссылками на затронутые файлы. При 100% готовности переносится в `docs/archive/`. |
| **Гайды и инструкции** | `docs/guides/` | `{topic_slug}_guide.md`<br>*(например: `docker_setup_guide.md`)* | `Active`, `Archived` | Инструкции по развертыванию, датасетам, обучению моделей, настройке серверов. |
| **Временные скрипты** | `scratch/` | `{name}.{js|ts|py|sh|ps1}`<br>*(например: `populate_feed.js`, `test_mcp.py`)* | — | Песочница для одноразовых экспериментов агента. **Никогда не попадает в Git**. |

## 3. Стандарты гигиенических файлов

### А. Защитный `.gitignore`
Должен надежно фильтровать:
1. Зависимости: `node_modules/`, `vendor/`, `.venv/`
2. Билд и артефакты: `dist/`, `build/`, `.next/`, `out/`
3. Секреты: `.env`, `.env.local`, `*.pem`, `*.key`
4. Логи и дампы: `*.log`, `*.dump`, `*.sql`, `*.sql.gz`
5. Песочницу агента: `scratch/`, `tmp/`, `temp/`
6. Кэши: `.cache/`, `.pytest_cache/`, `__pycache__/`, `.turbo/`

### Б. Высокоскоростной `.dockerignore`
Исключает из передачи демону Docker файлы, не нужные для работы рантайма:
- `.git`, `.gitignore`, `README.md`, `AGENTS.md`
- `docs/` целиком (спеки, планы, решения не нужны контейнеру)
- `tests/` (если они не запускаются внутри контейнера)
- `scratch/`, `.env`, `node_modules` (устанавливаются заново в образе)
- Логи, дампы, локальные кэши.
*Эффект: передача контекста Docker сокращается с 1–2 ГБ до 1–5 МБ, билд ускоряется в 10 раз.*

### В. Эталонный `.env.example`
- При появлении в коде любой новой переменной (`process.env.NEW_VAR` или `os.getenv("NEW_VAR")`) агент **обязан немедленно** внести ее в `.env.example`.
- Формат записи:
  ```bash
  # [Required] Порт сервиса API (по умолчанию 3000)
  PORT=3000
  # [Required] Строка подключения к PostgreSQL
  DATABASE_URL="postgresql://user:password@localhost:5432/mydb"
  # [Optional] Ключ OpenRouter для LLM инференса
  OPENROUTER_API_KEY=""
  ```

### Г. Эталонный `README.md`
Должен быть компактной «визиткой» проекта:
1. Описание назначения проекта (1 абзац).
2. Стек технологий (краткая таблица: Frontend, Backend, Database, Tools).
3. Быстрый старт (строго 3 шага: клонирование/установка, настройка `.env`, запуск dev-сервера).
4. Карта ключевых команд (`npm run dev`, `npm test`, `npx aislop scan`).

## 4. Протокол индексации и поддержания актуальности

1. **Регистрация в индексах**:
   - Каждая новая UI или API спека регистрируется в [`docs/navigation-index.md`](file:///C:/Agent%20templates/workspaces/minimal-agentic/docs/navigation-index.md) в таблице модулей.
   - Каждое архитектурное решение (ADR) регистрируется в [`docs/notes-index.md`](file:///C:/Agent%20templates/workspaces/minimal-agentic/docs/notes-index.md).
2. **Жизненный цикл планов (Архивация)**:
   - Когда все задачи в файле `docs/plans/{phase}_plan.md` выполнены (`[x] 100%`), агент:
     1. Меняет статус на `Status: Completed`.
     2. Перемещает файл в папку `docs/archive/{phase}_plan.md`.
     3. Фиксирует ключевой результат в `AgentDB` (`store_memory`).
     4. Обновляет строку `Current Focus` в `AGENTS.md` на следующую активную цель.
3. **Защита от устаревания (Staleness Audit)**:
   - Скрипт `scripts/audit-context.ps1` проверяет ссылки из индексов: если файл удален или переименован, выдается предупреждение.
   - Запрещено хранить в `docs/plans/` более 2 активных планов одновременно.
